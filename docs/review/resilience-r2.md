## Findings

### 1. A detached preflight descendant escapes cleanup

- **Severity**: High
- **Location**: `internal/app/claude_auth.go:79`
- **Description**: The probe is put in a new process group and cancellation kills that group, but a child can call `setsid` or `setpgid` before the leader exits and move outside it. `WaitDelay` still makes the function return within the deadline even if that detached child inherited stdout, but neither the cancellation callback nor the post-`Run` sweep signals the escaped process, so it can survive a preflight success or timeout. This falls short of MF5's required full-probe-tree/orphan cleanup. The normal agent path already treats detached descendants as part of its lifecycle boundary via the ownership tracker; the preflight does not start one.
- **Evidence**: `configureProcessGroup` only sets `Setpgid: true` (`internal/app/process_group_unix.go:40-42`), and `terminateProcessGroup` only calls `syscall.Kill(-pid, SIGKILL)` (`internal/app/process_group_unix.go:327-338`). The preflight uses only those helpers (`internal/app/claude_auth.go:79-88`). By contrast, `RunAgent` starts a process tracker before launching the provider and terminates tracked ownership afterward (`internal/app/agent_runner.go:85-94,115-140`); existing lifecycle tests explicitly create `Setsid: true` descendants (`internal/app/testdata/fakeagent/main.go:707,718`) and verify their cleanup (`internal/app/blackbox_test.go:303-355,1199-1233`). The new preflight tests spawn plain `sleep 30 &` children that remain in the original group (`internal/app/claude_auth_test.go:61-100`), so they do not exercise the escape. The broader command `rtk proxy go test ./internal/app -run 'TestBlackBoxTimeoutBlocksAndCleansProcesses|TestBlackBoxTimeoutBoundsPrivateRunnerAndDetachedGroup|TestBlackBoxDetachedDescendantsAreKilledOnTerminalPaths|TestBlackBoxProviderProcessesNeverReceiveExternalCredentials' -count=1 -v -timeout 40m` passed all four tests, confirming the established agent path still cleans detached descendants for both providers but not covering preflight detachment. `rtk go vet ./internal/app` passed, and `rtk gofmt -l internal/app/claude_auth.go internal/app/claude_auth_test.go internal/app/process_group_unix.go internal/app/process_group_other.go internal/app/agent_runner.go internal/app/app.go` produced no output.
- **Suggestion**: Give the preflight a real descendant-ownership boundary rather than relying only on process-group membership, and terminate/reap or at least signal every recorded descendant on success and timeout. Add a deterministic pre-run black-box case whose auth probe starts a `Setsid: true` stdout-holding descendant, assert the CLI returns within an injected short bound, assert the run directory and tmux session were never created, and assert the detached PID is gone.
